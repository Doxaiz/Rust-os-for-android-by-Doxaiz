# Готовая база DoxaizOS: сначала существующий Android, потом минимальные изменения

## Решение по направлению

По запросу пользователя основной маршрут для телефона — **готовая минимальная LineageOS/TrebleDroid Vanilla**, а не разработка новых системных служб и не обязательная полная сборка Android 17. Это выбор семейства базы, **не утверждение, что конкретный образ уже подходит телефону**.

Текущий проект уже использовал LineageOS/AOSP, а не собственное ядро и Android framework с нуля. Но путь полной сборки оказался заблокирован ресурсами. Теперь порядок другой:

1. Получить и проверить происхождение существующего минимального образа.
2. Проверить его совместимость и базовое поведение без наших модификаций.
3. Сравнить с исходной системой по одной методике.
4. Только затем добавлять существующий Doxaiz Launcher и действительно нужные изменения. Launcher не переписывать.
5. Производную поставку называть DoxaizOS только с раскрытием исходной базы, лицензий, изменений, обновлений и проверок. Установка Launcher на чужой ROM сама по себе не считается собственной прошивкой.

Текущие `build.sh`, manifest lineage-24.0 и CF-продукт сохраняются как **экспериментальная сборочная лаборатория**, а не готовая прошивка Redmi. Они не переведены скрытно на другую ветку. Самодельные Rust-замены системных служб не являются условием первого работающего варианта.

## Почему не «прошивка от Pixel»

| Вариант | Решение для цели 2 ГБ | Ограничение |
|---|---|---|
| Stock Pixel ROM | Не переносить как готовую универсальную базу | Образ конкретного Pixel не является образом Redmi; драйверы/ядро/разделы различаются |
| Pixel-подобный custom ROM | Не приоритет | Знакомый интерфейс не доказывает низкое потребление RAM; сравнивать конкретные сборки и набор фоновых служб |
| GrapheneOS | Не база для этого Redmi | Официальный список поддерживаемых устройств — Pixel, не Redmi 9A |
| LineageOS/TrebleDroid Vanilla | **Основной кандидат** | Нет обещания минимального RAM или работающих камеры/связи без измерений; готовые community GSI — не официальная поддержка LineageOS устройства |
| Минимальный AOSP/PHH GSI | Контрольный вариант | Даже небольшой system.img не гарантирует меньше RAM, лучшую связь или обновления |
| Старый Android Go | Только отдельный legacy-эксперимент, не безопасный default | Нельзя обменивать актуальные исправления безопасности на обещание скорости без явного раскрытия рисков |

Vanilla означает выбор сборки без включённого GApps-пакета; это не обязательный запрет нужных пользователю Google-приложений. Их совместимость, push, банковские приложения и влияние на память проверяются отдельно. Play Integrity не обещается.

## Проверенные кандидаты и границы

### Основной кандидат для предварительной оценки: Andy Yan LineageOS 21 pre-QPR2 TrebleDroid, Vanilla

В upstream build script ветки `lineage-21-pre-qpr2-td`, commit **edac8329d0212a9609a40f3efc6eec877cc88b85**, есть явное отображение:

- `A64VN` → `a64_bvN`;
- `A64GN` → `a64_bgN`;
- `64VN` → `arm64_bvN`.

Таким образом, A64 и ARM64 действительно разные outputs; не выводить ABI телефона из разрядности процессора. В публичном каталоге присутствуют A64 Vanilla и ARM64 Vanilla образы LineageOS 21 pre-QPR2 TD. **Точный файл/хеш пока не выбран и не скачан**, подпись и содержимое не проверены. Название/дата файла не доказывает актуальный security patch level или отсутствие vendor CVE.

Ветка `light` не объявляется автоматически лучшей: меньше compatibility patches не обязательно лучше на старом MediaTek. Для предполагаемого A64-пути сначала изучать TD-совместимость, а не выбирать слово light.

### Резерв для совместимости: LineageOS 20 TD Vanilla

Существуют community-отчёты об использовании `a64_bvN` на Redmi 9A 2/32 с определённым Android 10 vendor. Это только сведения об отдельных конфигурациях. Не переносить их на аппарат пользователя; не считать старую сборку безопасным повседневным вариантом без проверки patch level/поддержки.

## Обязательные условия перед выбором артефакта

- Подтверждены ABI userspace/binder, vendor, схема разделов и требования выбранной версии Android. `doxaiz_arm64` не превращается в A64 от переименования.
- Есть upstream download, точное имя, SHA-256, дата, лицензии/исходники и сведения о поддержке. Контрольная сумма с того же недоверенного зеркала не является независимой аттестацией.
- Прочитаны ограничения RIL/VoLTE, камеры, яркости, аудио, шифрования, SELinux, зарядки. Запись в community wiki — не сертификат совместимости.
- Есть план восстановления. Этот документ **не инструкция прошивки** и не разрешение отключать verity или стирать данные вслепую.
- Если не удаётся получить/проверить артефакт, статус остаётся «кандидат», без stock fallback и без выдуманного хеша.

Из этой sandbox доступны GitHub/npm/PyPI, но не подтверждён download больших образов с SourceForge. Поэтому обнаружение каталога не выдаётся за получение готовой прошивки.

## Как принять решение по скорости

Измерять одну и ту же конфигурацию телефона: одинаковые приложения, заполненность памяти/накопителя, температура, сеть и интервалы после boot. Раздельно — чистая Vanilla и вариант с нужными Google-службами. Нужны boot time, cold/warm app launches, MemAvailable/swap/PSI, перезапуски приложений, батарея, idle/wake, звонки/данные, камера/аудио. Не сравнивать размер сжатых архивов как runtime RAM; «система заняла 1,2 ГБ» без breakdown не равно 1,2 ГБ невысвобождаемой памяти.

До этих проверок корректно говорить **«наиболее разумный кандидат для 2 ГБ»**, а не «самая быстрая прошивка». Цель — повторное использование готовой ОС с минимальным собственным слоем, не накопление новых компонентов.
