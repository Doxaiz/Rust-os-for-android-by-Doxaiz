## Что именно исполнилось

Конфигурация из workflow этого commit: API 29 / Android 10, target default, x86_64, 2 ядра, `ram-size: 2048M`, KVM на Ubuntu GitHub runner.

В отличие от offline-тестов со mock adb, здесь action запускает Android Emulator, а `scripts/emulator-smoke.sh` выполняет настоящие ADB-команды:

1. Загружает релизный APK через downloader с обязательной проверкой доступной SHA-256 и структуры ZIP.
2. Проверяет признак QEMU; устанавливает APK в AVD.
3. Назначает HOME на `com.doxaiz.launcher/.MainActivity`.
4. Проверяет `Status: ok`, разрешение HOME в пакет Launcher, resumed Activity и наличие PID.
5. Вызывает сбор диагностики. Скриншот/logcat запрашиваются в EXIT trap в best-effort режиме; их полнота не является отдельным assert.

Успех подтверждает прохождение этих функциональных проверок в момент теста. Это не аудит всех функций интерфейса и не длительный тест стабильности.

## Что остаётся не выполненным

* DoxaizOS system.img не собран и не загружен; overlay не проверен полноценной Android-сборкой.
* APK установлен через ADB, а не предустановлен как системный HOME.
* Нет проверки ARM32/Binder64, vendor, драйверов или разметки Redmi 9A.
* Нет подтверждения целевых бюджетов памяти/кадров/холодного старта.
* Нет проверенного flash/recovery-комплекта для пользователя.

## Влияние на общую оценку

Первоначальное повышение оценки до ~30–35% отозвано: успех приложения на штатном Android не подтверждает готовность собственной прошивки. Текущая субъективная оценка прошивки — **~25–30%**. Подтверждённый функциональный результат приложения сохраняется, но не переносится на совместимость Redmi 9A или сборку ОС.
